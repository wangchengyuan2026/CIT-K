## 一句话策略

**先拿 DOI 占住时间戳，再谈影响因子。**

你现在最怕的不是论文写得不够漂亮，是**别人先发表同一个想法**。所以第一优先级
不是投顶刊，是**尽快在带时间戳、带 DOI 的公开渠道把你的算子写出来**。
预印本不冲突：绝大多数期刊允许先发预印本再投稿。

## 一、关键情报：arXiv 的门槛在 2026 年变了（这条改变计划）

必须在最前面说，因为它直接影响你原来的第一选择：

| 变化 | 内容 | 对你的影响 |
|---|---|---|
| 2026-01-21 起 | arXiv **取消了"机构邮箱即可"这条捷径**。首次投稿者必须要么"机构邮箱 + 在 arXiv 同一领域已有合著论文"，要么**拿到该领域一位资深 arXiv 作者的个人背书（endorsement）** | 你是独立研究者、没有机构邮箱，**必须走个人背书**，不能直接投 |
| 2025-10 起 | arXiv 的计算机科学区**不再接受 review 和 position paper**，除非已通过期刊/会议评审 | 你的 HIM 论文必须是**原创研究型**写法，不能写成"综述"或"立场文章" |
| 同期 | arXiv 要求非英语稿件**必须附完整英文翻译** | 正好和你选的"中英双版"吻合，英文版是硬需求 |

**背书怎么办（arXiv 官方给的路径，照做就行）**：

1. 注册 arXiv 账号，填好真实姓名和 ORCID（没有 ORCID 就去 orcid.org 免费注册一个，5 分钟）。
2. 开始一次投稿，选好分类（建议 `cs.AI`，备选 `cs.NE`），系统会自动给你一封
   **endorsement request 邮件**，里面有一个**专属链接**。
3. 找**你论文里引用过、而且他们本人也在 arXiv 上发过文**的作者。打开他们的 arXiv 摘要页，
   拉到最下面点 **"Which of these authors are endorsers?"**，就能看到谁有资格背书。
4. 给这位作者**单独**发一封邮件：说明你是谁（独立研究者）、论文解决什么问题、
   附上**论文全文**（英文版）、附上那封邮件里的背书链接。
5. **一次只联系一两个人，不要群发**（arXiv 明文规定群发属于不当行为，会适得其反）。

> 现实预期：独立研究者拿背书不轻松，可能要试几个人、花几周。所以**不要把它当第一站**。

## 二、改成这样排优先级（推荐顺序）

### 第 0 步（今天就能做）：代码本地仓库就绪 ✅

已完成：`LICENSE`(MIT) / `.gitignore` / `CITATION.cff` / `README.md` / `README.en.md`
已经写好，代码里没有硬编码路径，任何人 clone 下来按 README 就能复算。

**还差一步**：需要你的**姓名 + 邮箱**才能生成第一条提交记录（git 要求）。
给我这两个信息，我一条命令就完成。

### 第 1 步（本周）：代码上 GitHub

两条路，你选：

- **A. 装 GitHub CLI，你授权一次，我来推**（推荐，最省事）
  我装好 `gh`，你在浏览器里登录一次你的 GitHub 账号（我不接触你的密码），
  之后建仓库、推代码、写描述、加标签我全包。
- **B. 我只给你命令，你自己粘贴执行**
  你手动在 github.com 建一个空仓库，我给你三条命令，你复制粘贴即可。

### 第 2 步（本周）：给代码领一个 DOI（**强烈建议，很多人不知道这招**）

**Zenodo**（欧洲核子研究组织 CERN 运营，免费，不限学科）：
把 GitHub 仓库的某个 release 挂到 Zenodo，它会**自动发一个可被引用的 DOI**。

为什么值得做：
- 代码有了 DOI，就变成**可被引用的学术产出**，不是"一个项目"；
- 别人引用你的代码 = 引用你，这对独立研究者建立记录极关键；
- 免费、无需背书、手续只是点几下。

### 第 3 步（本周~下周）：英文预印本拿 DOI —— **这步不需要任何背书**

**Preprints.org**（MDPI 运营，瑞士，免费）：
- 官网原话：**"We welcome new users to directly submit without requiring any endorsement"**（无需背书）
- 免费发放 **Crossref DOI**，立即可被引用
- 上线速度：**通常 24 小时内**（只做基础合规筛查，不是同行评审）
- 授权 CC BY 4.0，你保留版权
- 被 **Web of Science 的 Preprint Citation Index** 收录

**这一条是你当前性价比最高的动作**：不需要求人、不需要等、24 小时拿到 DOI 和
公开时间戳。之后再慢慢走 arXiv 背书，两不冲突（可以同一篇论文两边都挂）。

### 第 4 步（并行）：中文版投期刊

中文版投国内刊，英文预印本挂 arXiv/Preprints.org，两边互相引用。

候选刊（**这个顺序是我按"独立作者可及性"排的，具体投稿要求我投稿前会逐条核对**）：

| 层次 | 候选 | 说明 |
|---|---|---|
| 最稳 | 《人工智能与机器人研究》 | 你 2018 年那篇就是这里发的，路线已验证 |
| 中等 | 《智能系统学报》《模式识别与人工智能》《计算机应用研究》 | 需要更完整的相关工作综述与实验 |
| 冲刺 | 《自动化学报》《计算机学报》《软件学报》 | 独立作者 + 单环境实验，录用概率低，不建议第一站 |

## 三、写论文前必须先定的一件事（学术风险，务必看）

**你的区域新奇度算子，现在必须写进论文正文，而且要在预印本里就写。**

原因：你原来论文里说"好奇心是自然涌现的"，但实验证明**涌现不出来**——
公式在 `dL = 0` 处恒为 0，`argmax` 永远选原地不动。真正让它跑起来的是那个
可计算算子（已探索掩膜 + 到最近未探索格的距离）。**这个算子是本项目补进去的，
论文里目前没有。**

如果你先公开代码、却不在论文里把这个算子写成正式公式，会出现一个很难受的局面：
读者/审稿人看到代码里有一个论文没写的关键算子，会质疑"到底哪个是你的理论"。
更糟的是，别人读你的代码后把它写成论文先发，时间戳是人家的。

**建议口径**：把这个算子作为**论文的正式贡献**写进正文，命名为
"HIM 的区域新奇度算子（region-novelty operator）"并给出消融数据。
这样它既受保护，也让论文从"理论宣言"变成"可证伪的机制"。

## 四、我能做什么 / 不能做什么（诚实边界）

| | 我能做 | 我不能做 |
|---|---|---|
| 代码 | 整理仓库、写文档与许可证、本地提交、**在你授权后**推送 GitHub | 替你注册 GitHub 账号；以你的身份登录 |
| 论文 | 中英文双版写作、改写、翻译、画图、把实验数字对齐、模拟审稿意见、逐条回应 | 替你署名；伪造数据；把没做的实验写成做了 |
| 预印本 | 把稿件做到"你只差点提交"：格式合规、作者信息、摘要、关键词、分类建议、cover letter | 以你的名义在 arXiv / Preprints.org 提交 |
| 期刊 | 选刊、投稿材料、cover letter、审稿意见模拟、返修函 | 以通讯作者身份投递、签署版权转让 |
| 背书 | 帮你找"谁有资格背书"、起草那封背书请求邮件、准备要附的材料 | 替你发那封邮件、替你去求人 |

**"最高权限"的边界就是这样**：凡是需要**署名、身份、法律签署**的动作，必须你本人来。
这不是我推脱——以他人名义投稿或背书，性质是学术冒名，一旦被查实对你伤害远大于收益。

## 五、三条风险提示

1. **MIT 许可证不可撤回**。已经有人用了之后，你不能再改成限制性许可。你已选 MIT，
   对"快速传播 + 被引用"是最优解；如果你以后想做商业闭源，就在新版本里换许可。
2. **不要美化数据**。这次实验最有价值的发现恰恰是**你的公式跑不动、希望机制贡献为 0**。
   把这些写进去不但不减分，反而是论文最能打动审稿人的部分——它证明你能证伪自己。
   审稿人最反感的是"声称 88.2% 却不给口径"。
3. **独立研究者身份不必隐藏，但要用质量对冲**。审稿人对无单位作者天然更严格，
   你能做的是：口径全公开、代码全公开、消融全公开、失败全公开。这套组合拳能让
   "民科"的质疑无处下手。
